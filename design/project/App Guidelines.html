The five anchors

00

Every screen we ship is reviewed against these. If a design fails an anchor and we can't argue why, we revise.

01

Decisions, not dashboards

An underwriter's job is to make a decision — approve, reject, escalate. Every screen states what's being decided, the relevant evidence, and the action up-front. Charts and stats exist only when they help the decision.

→ See Designing decisions
02

Earn density with hierarchy

Lending screens are dense. We earn it with typographic contrast, generous whitespace, and one strong action per surface. No striped tables, no candy-coloured tags.

→ See Density spec
03

Show provenance, always

Every AI-generated value is labelled, dated, and traceable to its source document. We never display a number without telling the user where it came from and how confident we are.

→ See Explainability
04

Friction lives where it should

Approvals get fast paths. Rejections, escalations and policy overrides require confirmation — and a written reason. We don't make destructive actions reversible; we make them deliberate.

→ See Human-in-loop
05

Audit before aesthetics

Every consequential action writes to an audit trail. If a design can't be replayed by compliance six months later, the design isn't done.

→ See Audit & review

Hierarchy & scanning

02 · Layout

An underwriter scans, doesn't read. We engineer for the 3-second scan: status, identity, amount, decision.

Human-in-loop

06 · Decision UI

Humans approve, override, and escalate. The system never makes a final adverse decision without a human in the loop. Friction is the feature.

6.1

Rejections require typed reason

The reviewer types a free-text reason and selects a policy code. Both write to the audit log. We don't accept one-click rejects.

modal · required field · audit
6.2

Policy overrides are explicit

When the reviewer overrides a model recommendation or policy check, the UI says so in plain language and asks for confirmation. The override is logged with who, when, and why.

confirm dialog · audit · attribution
6.3

Escalation paths are pre-defined

Escalate buttons route to the configured next-level reviewer. The escalation reason is mandatory. The originating reviewer remains visible in the trail.

role routing · audit

AI vs deterministic UI

07 · AI patterns

Users need to know, at a glance, whether what they're looking at was computed by the system (deterministic) or inferred by a model (AI). We label AI surfaces visibly.

Generated by Newron · CAM v3.2 Inferred · Artha extraction AI suggestion · accept to apply

AI-touched surfaces always show: the model that produced the value, the confidence score, and an affordance to override or correct. No model badge, no model output.

Confidence & uncertainty

08 · AI patterns

Errors

11 · Workflow

Errors are honest about what went wrong, whose fault it was, and what the user can do. Never blame the user for our infrastructure.

11.1

Name the system

“Bureau (CIBIL) responded with 503” is better than “Something went wrong.” Reviewers want to know which dependency failed.

alert.danger · system attribution
11.2

Offer a path

Every error has at least one action: retry, skip-and-continue, escalate, or contact support. Errors without actions create stuck users.

alert with btn-ghost
11.3

Never lose work

If a save fails, draft is retained client-side and resurfaced. We don't blow away a half-written CAM because the network blinked.

local persistence · resurface banner

Shipping checklist

13 · Quality bar

Before a product surface ships, design and engineering sign off on this. Without exception.

  • The screen states the decision being made in the H1.
  • There is exactly one primary action (violet) per surface.
  • Every AI-derived value displays model name, source, and confidence.
  • Confidence below 0.85 is paired with a “Please verify” affordance.
  • Destructive actions require a typed reason and write to audit.
  • Policy overrides require explicit confirmation and write to audit.
  • The screen has a designed empty state and a designed loading state.
  • All errors attribute the failing system and offer at least one action.
  • All numbers use tabular figures via .num.
  • All currency renders in ₹ with Indian comma grouping (₹ 12,50,000).
  • The audit trail can answer “who changed what when, and why” for everything on screen.
  • Screens meet WCAG AA at body size and AAA at 18px+.
